# 验收与反馈闭环

## 五种不同的通过

| 检查 | 可证明什么 | 不能证明什么 |
|---|---|---|
| 剧本复述 | 因果和包袱是否能讲明白 | 视频实际好笑 |
| ASR／词时间 | 可能漏词、重复、异常位置 | 演技／全部字音一定正确 |
| 声纹＋角色账本 | 配置身份和疑似串角 | 极短录音的绝对身份 |
| 能量、时窗、波形 | 有声音、选中素材合入、没明显掉尾 | 台词内容／演员语气获认可 |
| 原片／候选试听 | 当前观看者的真实偏好 | 下一句也必然一样好 |

机器报告只描述实际检查，用户反馈单独保存。未做的检查标未做，不拿相似度数字填空。

## 最终文件必须检查

先看输入 ledger 角色与 selected_take，再解码输出 MP4 的每个发言窗。需要有声音、与预期混音一致、时长覆盖最后词尾。只查生成 WAV 会漏掉合成覆盖、选择旧版本和编码时间戳问题。

FFmpeg loudnorm 动态模式会改变内部采样率；本渲染器在后面显式 `aresample=48000,asetpts=N/SR/TB`，再固定输出采样率、尾部补偿并限制成片时长。历史案例只补静音不重置时戳仍丢过短尾，因此测试检查**最终解码**的最后有声部分。这个修复是本渲染链的防回归措施，不应宣传为所有编码器的通用结论。

字幕按实际词边界／人工审核填写 caption offsets。长句未提供时只保留整句字幕并给提示；程序不会生成看似精准的等字数切分。查看开头、切场、字幕最密处、用户曾指出问题的位置和最后一帧，留截图记录实际检查范围。

保留原声名句／碰杯／笑声可做编码前同源区间比较，编码后允许有损编码差异。边界生硬时先补原始气息／尾音上下文，再以几毫秒淡化接缝；不能让淡出覆盖整个轻辅音。完整现场底声需要独立试听，短循环底声只是降级方案，不能称专业音源分离。

## 小样反馈问法

给明确时间和一个单一问题：剧情现在能不能听懂；方案 1／2 哪个气口更近；哪一句还断。不要一次要求用户评声线、剧情、节奏、字幕、噪声五件事。

能客观自行发现的问题先修好再问。用户说“基本可以”不代表其指出的缺陷可以忽略；把已接受与待修项分开记。

## 回归范围

局部换句后核查该句前后接话、角色、字幕和最终合入；全片覆盖检查仍执行。已认可的其他段落用波形／素材收据证明没有被误换，不为了显得认真把所有声音重录一次。

发布前保留成片、SRT、可读剧本、来源与传闻说明、版本变更、验收记录。源视频、私人 PDF、模型权重、音色参考和本机配置留在制作项目，不放进可复用 skill 包。
